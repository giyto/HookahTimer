# Проверка нескольких кальянов

## Новая проверка визуального отпускания и вибрации

При распознавании физического удержания распознаватель теперь сначала переводит
визуальное состояние стола из `pressed` в обычное, затем один раз вызывает
системный `HapticFeedbackType.LongPress` и только после этого добавляет кальян.
Физическое отпускание пальца по-прежнему поглощается и не вызывает короткое
нажатие. Семантическое действие долгого нажатия не имитирует физическую
вибрацию, поэтому TalkBack/клавиатура не получают дублирующий отклик.

В `MultipleHookahsScreenTest` добавлен отдельный сценарий точного порядка
`pressed:true → pressed:false → feedback → hold`, а существующие сценарии
дополнены записывающим fake-haptic. Они проверяют единственный отклик при
успешном физическом удержании и отсутствие отклика при tap, отмене, движении,
втором пальце, удержании в режиме редактирования и семантическом long-click.

Предыдущие результаты 79 unit- и 90 Android-тестов относятся к редакции до
этого уточнения. Быстрый прогон пользователя от 2026-09-05 подтверждён XML-
отчётом: **17/17 `MultipleHookahsScreenTest` успешно**, 0 падений, ошибок и
пропусков на `HookahTimer_Tablet` (Android 15). Следующий полный отчёт от
2026-09-05 11:22 подтверждает **91/91 Android-тест**, также без падений,
ошибок и пропусков. Свежие unit-отчёты содержат **79/79 успешно**, lint —
0 ошибок и 32 предупреждения. Пункты 5.4 и 7.1 закрыты; change выполнен
полностью. Команда быстрого прогона для будущих регрессий:

```powershell
.\gradlew.bat connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.class=ru.hznik.hookahtimer.hall.ui.MultipleHookahsScreenTest"
```

После него выполнить обе полные команды из раздела «Запуск». На реальном
устройстве дополнительно проверить, что стол начинает отжиматься до отпускания
пальца и в момент появления нового кальяна ощущается ровно один короткий отклик.

Первый быстрый прогон запустил 17 сценариев, но остановился в
`completionStaysInWindowAndBackOrOutsideNeverResetsTable`: Espresso десять
секунд ожидал фокус корневого окна перед `pressBack`, хотя падение произошло
до нового удержания и не относилось к haptic-логике. Общий тестовый helper
переведён на `OnBackPressedDispatcher` единственной активной Activity. Это
проверяет тот же системный BackHandler без зависимости от фокуса Espresso.
Повторный прогон завершил все 17 сценариев успешно. Gradle отдельно вывел
старую запись `Logcat of last crash` тестового процесса с
`Activity client record must not be null`, но тестовые отчёты содержат ноль
падений/ошибок, а сама задача завершилась `BUILD SUCCESSFUL`.

## Исправления после двух падений

- При переходе от названия к длительности снимается фокус названия. В логе
  падения после закрытия первого редактора снова запускался текстовый IME;
  такой возврат фокуса мог сдвигать форму перед нажатием на вторую проходку.
  Тест теперь дополнительно проверяет отсутствие фокуса на названии и ждёт
  скрытия клавиатуры по системным отступам перед следующим настоящим касанием.
- Material-кнопка принимает фокус ввода в клавиатурном, а не сенсорном режиме.
  Тест запрашивает `InputMode.Keyboard`, открывает и закрывает окно через
  семантические действия без инъекции touch, проверяет автоматический фокус
  кнопки и его возврат на стол, затем восстанавливает исходный режим ввода.
  Принудительного запроса фокуса на проверяемую кнопку из теста нет.

**Исправления подтверждены полным прогоном пользователя:** 79 unit- и
90 Android-тестов успешно. Агент сборку и тесты не запускал. Эти результаты
не покрывают новую вибрацию и визуальное отпускание; для закрытия change теперь
нужен быстрый жестовый и затем полный повторный прогон.

## Запуск

Из корня проекта в PowerShell:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug assembleDebugAndroidTest
.\gradlew.bat connectedDebugAndroidTest
```

Для второго запуска подключить только тестовый эмулятор. Существующие
Activity-тесты очищают базу приложения: не запускать их на рабочем планшете
с нужными столами. Экспорт Room v3 уже создан и проверен:
`app/schemas/ru.hznik.hookahtimer.hall.data.local.HookahTimerDatabase/3.json`.
Не удалять схемы v1/v2: они используются миграционными тестами.

Для быстрой проверки обоих исправленных сценариев запустить два класса:

```powershell
.\gradlew.bat connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.class=ru.hznik.hookahtimer.hall.settings.ui.TableSettingsScreenTest,ru.hznik.hookahtimer.hall.ui.MultipleHookahsScreenTest"
```

Затем выполнить обе полные команды выше без фильтров. Проверки отступов
можно повторить отдельно при регрессии полного экрана:

```powershell
.\gradlew.bat connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.class=ru.hznik.hookahtimer.hall.ui.HallWindowInsetsTest"
```

Тест пересоздания проверяет сохранение выбранного полного экрана, скрытие
статус-бара и навигации до/после и точное равенство viewport.
`captionBar` проверяется отдельно как отступ layout, а не как признак
immersive-режима: Android рекомендует определять его по статус-бару и навигации.
У скрытых панелей не учитываются устаревшие анимированные размеры; исходные
значения и видимость оконной шапки остаются в диагностике таймаутов.
Визуальную проверку immersive-режима из пункта 6 ниже не пропускать.

## Вручную на тестовой установке

1. Один кальян: запуск, переходы, красный таймер/обводка за минуту,
   красная заливка при нуле, ручное завершение и следующее нажатие для сброса.
2. На свободном столе удержание запускает только №1. На работающем добавляет
   только №2. Продолжение удержания и отпускание не проводят лишнюю проходку.
3. Для 2, 3 и 8 кальянов проверить обе ориентации и формы стола:
   имя сверху, срочный таймер по центру, иконка/счётчик снизу.
   Карточки идут по номерам, а не по срочности; последняя доступна прокруткой.
4. Завершить часть кальянов: они остаются в составе, общего крестика ещё нет.
   Завершить все: окно остаётся открытым. Закрыть окно и удержанием добавить
   следующий номер либо коротким нажатием сбросить весь стол.
5. Проверить обычные/предупреждающие/просроченные карточки одновременно,
   перенос приоритета после проходки и корректный таймер после сворачивания.
6. При включённом полном экране открыть/закрыть окно всеми тремя способами,
   повернуть планшет. Системные панели не должны появляться из-за окна.
   Масштаб, позиция и блокировка canvas сохраняются.
7. Проверить pan/pinch, второй палец и отменённое касание: они не добавляют
   кальян. В редакторе остаётся перетаскивание, удержание не делает заказ.
8. Проверить TalkBack: имя и количество стола, номер срочного кальяна,
   номер проходки/состояние карточки, доступное добавление и отсутствие
   доступных фоновых кнопок при открытом окне.
   После последней доработки повторить этот пункт: у завершённого стола
   обычное действие подписано «Сбросить стол», долгое — «Добавить кальян».
   Выполнение сброса возвращает №1 без таймера; добавление вместо сброса
   сохраняет завершённые карточки и запускает следующий номер. Не должно
   быть повторного озвучивания иконок; после закрытия окна фокус возвращается
   на стол. UI-тест проверяет фокус ввода в клавиатурном режиме, а озвучивание TalkBack
   требует этой ручной проверки.
9. Обновить тестовую установку с базой v2 без удаления приложения:
   старые настройки, дедлайны и координаты должны сохраниться как №1.

## Обновление рабочего планшета

Перед обновлением сохранить резервную копию рабочих данных либо проводить
переход между сменами после проверки миграций. Обратная миграция 3 → 2
не предусмотрена: простой возврат старого APK не преобразует несколько
кальянов в старый одиночный формат. Не очищать рабочую базу ради отката.
